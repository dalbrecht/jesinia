Settings

/settings/. Foundation screen at higher fidelity. One place for the KB folder, git sync, agents, file conflicts, and the login token. Neutral chrome like the launcher. Every "How to fix" link elsewhere in Jesinia lands on a section here.

Default

  1. One column, five panels. Settings is short enough to read top to bottom, so the left nav is a list of anchors (scroll-spy sets the selected row), not separate pages. Deep links like /settings/#agents come from the launcher status strip and the status-dot popover.
  2. Buttons appear only when they can act. "Resume" shows only while sync is paused and "Initialize git" only when the folder has no .git. The default state has just "Sync now".
  3. Runner choice lives in two layers. The global default sits under Agents, and each app can override it. The chat header picker is the third layer and starts a new session (shell decision 5).
  4. Conflicts are read-only. Each item names the file paths in mono and offers "Reveal in Finder". Jesinia never auto-deletes or renames; the list clears on the next index.
  5. Security has one danger button and no primary. The consequence copy sits above it, and clicking it opens an inline confirm in the panel, not a browser dialog.

States

State frames show the affected panel only; the section nav is unchanged and omitted.
