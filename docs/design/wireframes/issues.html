Issues

/issues. Product screen at lower fidelity, built from real components; it informs the Issues spec later. Issues runs in compact density and is the one Jesinia app shaped like horizontal columns: a board you triage with an agent. Chat lives inside the triage drawer (shell decision 2) instead of a separate rail.

Board

  1. Compact density. The app root sets data-density="compact", so cards, rows, and suggestion rows use the compact row tokens (5px / 10px padding, small text). Issues is operational, so more issues per screen wins over air.
  2. Board silhouette. Full-width horizontal columns make Issues recognizable in Mission Control even when the text is unreadable: Notes is a document, RSS three panes, Review a split, Issues a row of columns.
  3. Suggestions are advisory. Each suggestion gets its own Accept and Dismiss, plus Accept all. Nothing changes on GitHub until you accept. Each row says why ("Same stack trace in cycle.py"), so you can judge it in a glance.
  4. Chat inside the drawer (shell decision 2, per-app placement). Issues has no chat rail; the conversation belongs to the issue you are triaging. ⧉ pops it out into its own window; the runner picker lives in the chat header (shell decision 5).
  5. Keyboard. ←/→ move between columns, ↑/↓ (or j/k) within a column, Enter opens the drawer, a accepts the focused suggestion, ⇧A accepts all.
